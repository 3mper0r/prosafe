# Cloudflare Workers deployment (vinext)

PROSAFE can run on Cloudflare Workers through [vinext](https://github.com/cloudflare/vinext), Cloudflare's Vite-based implementation of the Next.js API surface. The existing Next.js commands (`npm run dev`, `npm run build`, `npm start`) are unchanged; vinext adds parallel scripts.

vinext is in beta. Versions are pinned exactly in `package.json`.

## Files

| File | Purpose |
| --- | --- |
| `vite.config.ts` | Generated by `vinext init`: vinext, the Cloudflare Vite plugin, and CSS Modules naming. |
| `cloudflare.config.ts` | Worker name (`prosafe`), compatibility date, static assets, and every runtime variable/secret declaration. |
| `.dev.vars.example` | Template for local secrets. Copy to `.dev.vars` (ignored). |

Initial setup: no CDN cache, no data cache, no Cloudflare Images optimization, and no prerendering. Every page is rendered by the Worker; files in `public/` and `/_next/static/*` are served as static assets.

## Scripts

| Command | Purpose |
| --- | --- |
| `npm run dev:vinext` | Vite dev server on port 3001 in the local Workers runtime. |
| `npm run build:vinext` | Production build into `.cloudflare/output`. |
| `npm run start:vinext` | Serve the production build locally in workerd (`vite preview`, port 4173). |
| `npm run deploy:vinext` | Build and deploy with `vinext-cloudflare deploy`. |

## Environment variables and secrets

The Worker sees only what `cloudflare.config.ts` declares. `.env*` files and shell variables are not copied into the Worker, and each deploy removes undeclared plain variables. Locally, `.dev.vars` supplies values only for declared secrets.

| Name | Type | Current value |
| --- | --- | --- |
| `QUOTE_DELIVERY_PROVIDER` | text | `none`. Delivery is disabled and the quote form shows that submission is unavailable. |
| `QUOTE_FORM_SECRET` | secret | Required at deploy time; at least 32 random characters. Never committed. |
| `SITE_URL` | not declared | Preview pages are `noindex`, `robots.txt` disallows all crawling, and the sitemap is empty. |

To enable delivery later, after a Resend account, verified sender domain, sender address, and destination mailbox exist:

1. In `cloudflare.config.ts`, set `QUOTE_DELIVERY_PROVIDER: bindings.text("resend")`, add `QUOTE_FROM_EMAIL`, `QUOTE_TO_EMAIL`, and `QUOTE_PUBLIC_ORIGIN` as `bindings.text(...)`, and add `QUOTE_RESEND_API_KEY: bindings.secret()`.
2. Upload `QUOTE_RESEND_API_KEY` as a secret (see below), then deploy.

`SITE_URL` is read at request time because no routes are prerendered. Add it as `bindings.text("https://…")` only after launch approval.

## Deploying

Authenticate once with `npx cf auth login`, or set `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` in CI.

The first deploy must include the declared secret. Keep the secrets file outside the repository:

```sh
umask 077
SECRETS_FILE="$(mktemp)"
printf 'QUOTE_FORM_SECRET=%s\n' "$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")" > "$SECRETS_FILE"
npm run build:vinext
npx cf deploy --prebuilt --mode production --secrets-file "$SECRETS_FILE"
rm -f "$SECRETS_FILE"
```

Later deploys keep the uploaded secret:

```sh
npm run deploy:vinext
```

Change a secret later:

```sh
npx cf workers secrets update QUOTE_FORM_SECRET --worker prosafe --type secret_text
```

## Workers Free limits that apply

- 100,000 Worker requests per day. Because every route is Worker-rendered and `runWorkerFirst` covers `/*` except `/_next/static/*`, page and `public/` image requests count toward this limit.
- 10 ms of CPU per request. After the first deploy, check CPU time per route in Workers Observability. If catalog pages exceed it, prerender static routes (`--cdn-cache=static-assets`) or move to Workers Paid.
- Rate limiting and deduplication in `/api/quote` are in memory and per isolate. Resend idempotency keys still prevent duplicate emails on retry.
- `next/image` is served unoptimized. The homepage hero PNG (about 1.6 MB) is sent at full size, where Next.js sent a resized WebP of about 40 KB. Cloudflare Images (`--image-optimization=cloudflare-images`) includes 5,000 unique transformations per month on Free; beyond that, new transformations fail with error 9422.
